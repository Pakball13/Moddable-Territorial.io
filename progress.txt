--------------------------------------------------------------------------------
SECTION 1 — WHAT THIS PROJECT IS
--------------------------------------------------------------------------------

Modatorial.io is a CLIENT-SIDE modding platform for the browser game
territorial.io (created by David Tschacher, davidschacher@gmail.com).

The platform does NOT modify the original game. Instead, it monkey-patches
browser APIs (WebSocket, requestAnimationFrame, CanvasRenderingContext2D,
DOM events) BEFORE the game loads, and exposes a stable API for mods.

Users can:
  - Install mods from a Firebase-backed community store
  - Write their own mods as .ttmod bundles
  - Sign in with email/Google/GitHub
  - Track stats, XP, and levels per account
  - Earn "Moddables" (in-game currency)
  - Redeem promo codes for upload slots
  - Switch between 6 themes

Live deployment target: https://modatorial.netlify.app
Local dev URL: http://127.0.0.1:5500 (VS Code Live Server) or http://localhost:8000

SECTION 5 — THE MOD LOADER (modLoader.js) — HOW IT WORKS
--------------------------------------------------------------------------------

The loader runs BEFORE game.js on game.html. It:

1. Sets up global error suppression:
     window.addEventListener('error', ..., true)
   Blocks the game's own error dialog from popping.

2. Proxies WebSocket:
     Replaces window.WebSocket with a wrapper class.
     For each ws.send() call, fires the 'netSend' hook.
     For each ws.onmessage, fires the 'netRecv' hook.
   Blocked hosts (territorial.io, 1.territorial.io, 2.territorial.io)
   return a fake WebSocket in offline mode.

3. Proxies requestAnimationFrame:
     Runs 'preUpdate' hooks before each frame,
     'postUpdate' hooks after.

4. Proxies CanvasRenderingContext2D:
     Hooks drawImage → fires 'preRender' and 'postRender'.
     Hooks fillText → hides text matching /^\d{1,2}\s+\w{3,}\s+\d{4}\s*\[/
     (i.e. the game version string like "25 Sep 2026 [2.16.54]").

5. Forwards DOM events:
     keydown → 'keyDown' hook + 'keydown' event
     keyup → 'keyUp' hook + 'keyup' event
     mousedown / mouseup / mousemove → matching hooks

6. Loads mods:
     Reads mods/manifest.json → array of folder names.
     For each, loads mod.json + main.js inside a Function wrapper.
     main.js receives (api, mod) — api is window.TerritorialMods.

7. Also loads .ttmod bundles:
     Scans mods/ttmods/manifest.json for .ttmod files.
     Each is translated via ttmod-translator.js, then executed.

8. Manages state:
     Disabled mods list → localStorage 'tt-disabled-mods'
     Layout (sidebar/grid/circles) → localStorage 'tt-layout'
     Theme → localStorage 'tt-theme'
     Sidebar collapsed → localStorage 'tt-sidebar-collapsed'

9. Injects UI:
     Chrome bar (top strip with brand, layout, theme, store, mods, mute)
     Mod menu (F10)
     Store button (F8)
     Mods button, Store button, Appearance button in the main menu
     Layout system for these three buttons (sidebar / grid / circles)

10. Hides game clutter:
     Timeline bars (aU.wr)
     Contest countdown (aP.wr)
     Clan bar (matched by DOM shape)
     Store icons (bb.gM array)
     Menu logo (ac.aIh returns blank canvas)
     Version text (fillText hook)

--------------------------------------------------------------------------------

A .ttmod file looks like this:

  <ttmod>
  {
    "id": "my-mod",
    "name": "My Mod",
    "version": "1.0.0",
    "author": "You",
    "description": "Does something",
    "gameVersion": 25,
    "config": {
      "userName": "CoolPlayer",
      "userColor": "#00ff88",
      "theme": { "accent": "#00ff88", "background": "#0a0a1a" },
      "layout": "sidebar",
      "hideMultiplayer": true,
      "hideVersion": true,
      "showFps": true,
      "showClock": true,
      "panorama": "panorama.png",
      "panoramaSpeed": 0.00005,
      "watermark": "Made by You",
      "watermarkPosition": "bottom-right",
      "buttons": [
        { "label": "Discord", "url": "https://discord.gg/..." },
        { "label": "Hello", "toast": "Hi!" }
      ],
      "flags": ["🇵🇰", "🔥"],
      "confirmExit": true,
      "customCss": "body { color: red; }"
    },
    "assets": {
      "panorama.png": "data:image/png;base64,...",
      "icon.png": "data:image/png;base64,...",
      "music.mp3": "data:audio/mpeg;base64,..."
    }
  }
  </ttmod>
  <script>
  // Optional raw JS — runs with full api.* access
  api.log('My mod loaded');
  </script>

The translator (ttmod-translator.js) parses this and emits the equivalent
JS using api.addHook / api.setTheme / api.addButton etc.

If a .ttmod has ONLY a <script> block and no config, the script runs as-is.

SECTION 10 — FIRESTORE RULES (current, deployed)
--------------------------------------------------------------------------------

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isSignedIn() { return request.auth != null; }
    function isSelf(uid) { return isSignedIn() && request.auth.uid == uid; }

    match /mods/{modId} {
      allow read: if true;
      allow create: if
        isSignedIn() &&
        request.resource.data.authorUid == request.auth.uid &&
        request.resource.data.name is string &&
        request.resource.data.name.size() > 0 &&
        request.resource.data.name.size() < 60 &&
        request.resource.data.author is string &&
        request.resource.data.author.size() < 40 &&
        request.resource.data.ttmod is string &&
        request.resource.data.ttmod.size() > 0 &&
        request.resource.data.ttmod.size() < 800000 &&
        request.resource.data.downloads == 0;
      allow update: if
        (isSignedIn() && request.resource.data.diff(resource.data)
          .affectedKeys().hasOnly(['downloads']))
        ||
        (isSelf(resource.data.authorUid) &&
         request.resource.data.diff(resource.data)
          .affectedKeys().hasOnly(['name','description','version','icon','tags','changelog']));
      allow delete: if isSelf(resource.data.authorUid);
    }

    match /users/{uid} {
      allow read: if true;
      allow create, update: if isSelf(uid);
      allow delete: if false;
    }

    match /usernames/{username} {
      allow read: if true;
      allow create: if
        isSignedIn() &&
        request.resource.data.uid == request.auth.uid &&
        username == username.lower() &&
        username.size() >= 3 &&
        username.size() <= 24 &&
        username.matches('^[a-z0-9_.\\-]+$');
      allow update, delete: if false;
    }

    match /profiles/{uid} {
      allow read: if isSelf(uid);
      allow write: if isSelf(uid);
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

NOTE: The current mod-store.js does NOT write authorUid on publish (only
the "patched" version does). If you're using the minimal-patch mod-store.js,
delete the two authorUid lines from the /mods create rule and change
delete to `false`.

SECTION 16 — ACCOUNT SYSTEM
--------------------------------------------------------------------------------

Two separate systems track stats:

1. account.html — reads/writes localStorage 'tt-account-v1-<uid>'
   Shows: level, XP, games played, wins, losses, surrenders, playtime,
          last-match mods, username history, match history chart

2. account.js — runs on game.html, tracks stats in real-time
   Detects match start (aE.a2G===1) and end (aE.a2G!==1)
   Polls every 250ms to detect outcome via aE.a2L:
     a2L === 1 → win
     a2L === 0 → loss
     a2L === 2 → surrender/stalemate
   Writes to the same localStorage key

XP curve: xpForLevel(lvl) = 50*lvl² + 50*lvl
XP gain:
  +10 base per match
  +50 bonus for a win
  +5 bonus for a loss

The storage key MUST be per-uid (tt-account-v1-<uid>) to avoid cross-account
contamination. If you see another account's stats, the key is wrong.

The profile card on account.html renders:
  - Avatar (photoURL if available, else initial letter)
  - Display name
  - "Signed in with [provider]"
  - Email (with ✅ if verified)
  - Phone (if attached)
  - Truncated User ID

Phone attach flow:
  - Uses invisible reCAPTCHA (window.__ttRecaptcha)
  - Calls user.linkWithPhoneNumber(phone, recaptcha)
  - User enters 6-digit code
  - On confirm, writes phone to /users/{uid}.phone

Sign out: calls Auth.logout() → redirects to login.html

SECTION 19 — SOUNDS (sounds.js)
--------------------------------------------------------------------------------

All sounds are synthesized via Web Audio API — no asset files.

Synths:
  click, hover, type, attack, attacked, start, clock, timer,
  victory, defeat, surrender, notify, ping, error, success, whoosh, levelup

The 'attack' SFX is triggered by netSend hook, decoding packet byte[0]:
  if ((bytes[0] & 0xF8) === 0x88) → attack packet

The 'attacked' SFX is triggered by a MutationObserver watching for
"attacks you" text in the DOM (from the game's own popups).

The 'type' SFX plays on keydown when focus is on an input/textarea.
Rate-limited to 30ms between hits with slight pitch variance.

Volume saved at localStorage 'tt-volume'.
Mute state at localStorage 'tt-muted'.

Exposes window.TerritorialSounds.
